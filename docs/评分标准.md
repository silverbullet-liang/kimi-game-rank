# 评分标准 — Kimi游戏榜

> 站内「评分标准」正式文案 · 算法全公开版
> 本页公布本站的**全部评分算法**：所有公式、权重与阈值均来自运行中的配置，可对照复核。

## 评分总览

本站对每件收录作品进行**六维综合评分**：单维满分 **200 分**，总分 = 六维之和，满分 **1200 分**。

全部评分由系统按下列公开算法自动计算，**无人工干预，不接受调分申请**。

| 维度 | 满分 | 衡量什么 |
|:---:|:---:|---|
| 热度 | 200 | 社区互动量（点赞 / 评论 / 收藏） |
| 创意 | 200 | 标题独特性、表达多样性、形式创新 |
| 体验 | 200 | 可运行性、交互密度、媒体丰富度、说明完整度 |
| 深度 | 200 | 文本规模、结构复杂度、代码深度、讨论深度 |
| 成本 | 200 | 作者投入的体量与制作成本 |
| 态度 | 200 | 作者回复、维护痕迹、配文用心、持续维护 |

> 六个维度相互独立，各自归一化到 0–200，因此**单维满分不等于总分必然高**——总分是六维的综合结果。

## 一、记号与基础函数

| 记号 | 含义 |
|:---:|---|
| L / C / F | 作品的点赞数 / 评论数 / 收藏数 |
| T / X / B | 作品标题 / 作者配文（简介） / 正文 |
| I | 作品图片数 |
| H | 作品 HTML 文件（无则记为空） |
| bytes / lines | H 的文件大小 / 代码行数 |
| AR / SC | 作者回复评论数 / 楼中楼评论总数 |
| age | 作品上架至今小时数 |

三个基础函数（下文公式均用到）：

```
clamp01(x)   = 把 x 限制到 [0, 1]
lns(x, n)    = ln(1+x) / ln(1+n)          ← n 为该信号的满分基准，边际递减
bell(x, a, b) = x 落在 [a, b] 内取 1，越界按 decay=10 线性衰减到 0
```

- **lns 的作用**：把"无限增长"的互动量压缩到 0–1，使分数随互动量递增但**边际递减**——从 0 到 10 赞的收益远大于从 100 到 110 赞，因此**刷量的性价比极低**。
- **bell 的作用**：标题长度等指标存在"最佳区间"，过短或过长都会衰减。

## 二、热度（唯一纯互动维）

```
heat = 200 × min(1, 0.45×lns(L, 100) + 0.35×lns(C, 50) + 0.20×lns(F, 30))
上架 24 小时内：heat × (1 + 0.2 × (1 − age / 24))，上限 200
```

- 满分锚点：**100 赞 + 50 评 + 30 藏**。
- 权重体现"点赞 > 评论 > 收藏"的互动成本差异。
- 新作品在首日享有**至多 20% 的曝光加成**，随时间线性衰减至 0。
- 示例：10 赞 / 5 评 / 3 藏 ≈ **95 分**。

## 三、创意

```
s1 标题独特性 = 1 − 标题与库内最相似作品的 2-gram 相似度（Jaccard，最多比对 300 件；空库记 1）
s2 标题长度   = bell(len(T), 4, 20)
s3 表达多样性 = 文本（简介+正文）去重词数 ÷ 总词数
s4 形式创新   = min(1, ( 0.15×(有 artifactShareId) + 0.10×(有作品文件) ) ÷ 0.25)

creativity = 200 × clamp01( 0.35×s1 + 0.15×s2 + 0.30×s3 + 0.20×s4 )
```

- **标题独特性**：与库内已有标题做 2-gram 比对，越不像现有作品得分越高；重名、套用模板的标题会被显著拉低。
- **形式创新**：同时具备「可分享产物」与「作品文件」才能拿满 s4。

---

## 四、体验

```
e1 可运行作品 = 有作品文件或 artifactShareId → 1
e2 交互密度   = min(1, 交互标签总数 ÷ 12)
   （交互标签：button / input / select / textarea / canvas / audio / video / svg）
e3 媒体丰富   = min(1, I ÷ 6)
e4 说明完整   = 命中词表 {操作,点击,选择,输入,按键,拖动,关卡,难度,模式} 的比例

experience = 200 × clamp01( 0.50×e1 + 0.20×e2 + 0.15×e3 + 0.15×e4 ) × (有作品文件 ? 1 : 0.8)
```

- **可运行性权重最高（0.50）**：本站是作品榜单，能真正跑起来的作品理应占优。
- 无可运行文件的作品，本维**整体乘以 0.8** 作为惩罚。

---

## 五、深度

```
d1 文本规模   = min(1, len(X + B) ÷ 800)
d2 结构复杂度 = min(1, (段落标记数 + 列表标记数) ÷ 6)
d3 代码深度   = max( min(1, lines ÷ 400), min(1, function 出现次数 ÷ 30) )
d4 讨论深度   = clamp01( 0.7×lns(C, 30) + 0.3×min(1, SC ÷ 10) )

depth = 200 × clamp01( 0.30×d1 + 0.20×d2 + 0.30×d3 + 0.20×d4 )
```

- 代码深度取「行数」与「函数个数」的**较大值**，避免"堆行数但无结构"或"结构好但文件很小"被单一指标误判。
- 讨论深度兼顾评论总量与楼中楼深度。

---

## 六、成本

```
c1 文件体量 = min(1, bytes ÷ 150KB)
c2 代码规模 = min(1, lines ÷ 600)
c3 媒体成本 = min(1, 0.15×I + 0.20×(有音频) + 0.20×(有视频))
c4 文本投入 = min(1, len(X + B) ÷ 1500)

cost = 200 × clamp01( (0.35×c1 + 0.25×c2 + 0.20×c3 + 0.20×c4) ÷ 权重之和 )
（无作品文件时剔除 c1、c2，其余权重**等比放大重归一化**）
```

- 「成本」衡量的是**作者投入的客观体量**，与「质量」正交：大而全不等于好，但在同等质量下投入更多理应被看见。
- 无作品文件的作品只按媒体与文本计分，并**重新归一化**（不会因为缺项而被机械扣分）。

---

## 七、态度

```
a1 作者回复率 = AR ÷ max(1, C)
a2 维护词命中 = {更新,修复,优化,感谢,反馈,抱歉,调整} 在文本中的命中比例
a3 配文用心   = len(X) ≥ 50 → 1；≥ 20 → 0.5；否则 0
a4 持续维护   = 有近期内容更新记录 → 1；无 → 0

attitude = 200 × clamp01( 0.35×a1 + 0.25×a2 + 0.20×a3 + 0.20×a4 )
```

- 本维奖励**认真对待读者**的作者：回复评论、写清楚配文、持续维护。
- a4 依赖上游数据源是否提供"近期更新"信号；数据源未提供时该项不计分（不会因此虚高或虚低其它项）。

## 九、数据不足与异常处理

1. **信号缺失**：某一信号无法取得时，**剔除该信号并将其余权重等比重归一化**，而不是按 0 计分——避免"资料少就吃亏"。
2. **整维不可算**：某维度完全无法计算时，按可得数据计分，并在详情页以**灰点**提示数据不足，**不虚报**。
3. **异常值**：互动数据出现明显异常（如短期陡增）时，系统会标记并复核；确认异常的可清除相关数据并重算。

## 十、防刷分机制

1. **对数平滑 + 满分锚定**：热度采用对数曲线，刷量的边际收益极低。
2. **排序物化**：榜单排序键由系统维护，不接受外部注入。
3. **访问与操作限速**：点赞等操作有频次与去重限制（每人每项仅可点赞一次）。
4. **重复内容约束**：评论、反馈等有重复内容拦截，防止刷分式灌水。
5. **人工复核**：对异常账号与作品，管理员可复核并处置。

## 十一、动态重算

1. 作品的互动数据变化后，系统在同步时**自动重算六维**，榜单排名随之更新。
2. 系统同时记录**历史最高总分**，用于「诸神榜」排序。
3. 因此，**作品分数与排名是动态的**——持续维护、积累互动的作品可以「逆风翻盘」。

## 十二、常见问题

**Q：为什么我的作品分数不高？**
A：请对照上表逐维自查。最常见的失分点是：无可运行文件（体验 ×0.8）、配文过短（态度 a3 为 0）、标题与已有作品高度相似（创意 s1 被拉低）。

**Q：可以申请调分吗？**
A：不可以。评分完全由算法计算，无人工调整通道；这既保证公平，也避免"求分数"打扰作者与管理员。

**Q：为什么同一作品的分数会变？**
A：互动数据变化会触发重算。分数上升说明作品在被更多人认可，下降可能是热度衰减或同类作品增多导致标题独特性下降。

**Q：为什么有的维度显示为灰点？**
A：该维度数据不足以计算，系统如实标注而不虚报。

## 十四、数据来源与更新时机

| 项目 | 说明 |
|---|---|
| 数据来源 | 作品在 [Kimi 社区](https://www.kimi.com)的**公开信息**：标题、作者配文、正文、图片数、点赞 / 评论 / 收藏数、作者回复数、楼中楼数、作品文件等 |
| 首次计算 | 作品**被收录时**计算六维并写入 |
| 后续计算 | 此后每次**同步到新数据**时自动重算，无需人工触发 |
| 更新节奏 | 由管理员配置的同步节奏决定；自动模式下按社区信息流分批发现与更新 |
| 动态性 | 评分与排名是**动态**的。本页展示的是**计算规则**，不是某一时刻的分数 |

> 本站**不采集**：浏览量（上游不提供）、站外数据、作者私密信息。

## 十五、逐维「计什么 / 不计什么」

| 维度 | 计入（可量化信号） | **不计入**（主观判断） |
|:---:|---|---|
| 热度 | 点赞、评论、收藏 | 浏览量、站外热度 |
| 创意 | 标题独特性与长度、表达多样性、形式创新 | 「有没有创意」的主观感受 |
| 体验 | 可运行性、交互标签数、图片数、说明词覆盖 | 「好不好玩」的主观感受 |
| 深度 | 文本规模、结构标记、代码行数与函数数、讨论深度 | 「深不深」的主观感受 |
| 成本 | 文件体量、代码规模、媒体、文本投入 | 作者无法被量化的努力 |
| 态度 | 作者回复率、维护词命中、配文长度、持续维护 | 「态度好不好」的主观感受 |

**关键说明**：本站**不对主观的创意、美感、有趣程度做任何人工判断**，六维全部建立在**可量化、可复核**的信号之上。这是本榜"算法全公开"的前提——只有可量化的东西才谈得上公开。

## 十六、完整算例

以一件**游戏类作品**为例（数值仅用于演示计算过程）：

| 输入 | 取值 |
|---|---|
| 点赞 / 评论 / 收藏 | 42 / 18 / 7 |
| 上架时长 | 72 小时（已过首日加成） |
| 标题长度 | 12 字，与库内最相似标题相似度 0.20 |
| 表达多样性 | 0.62 |
| 形式创新 | 有产物 ID + 有作品文件 |
| 交互标签 / 图片数 | 9 个 / 4 张 |
| 说明词覆盖 | 6 / 9 |
| 文本长度 | 520 字 |
| 结构标记 | 3 处 |
| 代码行数 / 函数数 | 260 行 / 12 个 |
| 楼中楼数 | 4 |
| 文件大小 | 98 KB |
| 作者回复 / 评论 | 8 / 18 |
| 维护词命中 | 3 / 7 |
| 配文长度 | 60 字 |

| 维度 | 计算 | 得分 |
|:---:|---|:---:|
| 热度 | 200 × (0.45×lns(42,100) + 0.35×lns(18,50) + 0.20×lns(7,30)) = 200 × 0.7500 | **150** |
| 创意 | 200 × (0.35×0.80 + 0.15×1 + 0.30×0.62 + 0.20×1) = 200 × 0.816 | **163** |
| 体验 | 200 × (0.50×1 + 0.20×0.75 + 0.15×0.6667 + 0.15×0.6667) = 200 × 0.850 | **170** |
| 深度 | 200 × (0.30×0.65 + 0.20×0.50 + 0.30×0.65 + 0.20×0.7202) = 200 × 0.634 | **127** |
| 成本 | 200 × (0.35×0.6533 + 0.25×0.4333 + 0.20×0.60 + 0.20×0.3467) = 200 × 0.5264 | **105** |
| 态度 | 200 × (0.35×0.4444 + 0.25×0.4286 + 0.20×1 + 0.20×0) = 200 × 0.4627 | **93** |

**总分 = 150 + 163 + 170 + 127 + 105 + 93 = 808 → 评级 SS**

> 本例中该作品「体验」与「创意」表现突出，「态度」因作者未持续更新而偏低（a4 = 0），
> 说明**任一维度的短板都会压制总分**——这正是设置六维而非单一分数的意义。

## 十七、自查：如何提升分数

| 你希望提升 | 可以做什么 |
|---|---|
| 热度 | 让作品被更多人**点赞、评论、收藏**；首日曝光加成有窗口期，尽早分享 |
| 创意 | 起一个**不与他人重复**的标题；把配文写充实、用词多样；提供可分享的产物 |
| 体验 | 确保作品**可运行**；加入按钮 / 输入 / 画布等交互；多配图；写清**操作说明** |
| 深度 | 正文写清玩法与设计；善用分段与列表；代码按功能拆分函数 |
| 成本 | 无法"优化"——本维衡量客观投入，鼓励的是**认真做**而非凑数 |
| 态度 | **回复评论**；在配文中体现维护痕迹；保持更新 |

> 请注意：以上是**基于算法的规律**，不是保证。评分不为个案调整。

## 十八、术语表

| 术语 | 含义 |
|---|---|
| 信号 | 参与计算的原始数据项（如点赞数、代码行数） |
| 归一化 | 把不同量纲的信号映射到 0–1，使其可加权求和 |
| 重归一化 | 某项缺失时，把其余权重等比放大，使总和仍为 1 |
| 锚点 / 满分基准 | 使某一信号达到满分所需的取值（如 100 赞） |
| 边际递减 | 投入增加但收益增速下降的特性，由 lns 实现 |
| 2-gram 相似度 | 按相邻两个字符切分文本后计算的重合程度，用于判断标题独特性 |
| 物化列 | 预先算好并存储的排序键（如历史最高分），用于加速榜单排序 |
| 评级 | 由总分区间决定的档位（SSS～C） |
