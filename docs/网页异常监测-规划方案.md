# 网页异常监测（Web APM）规划方案
### —— 对标华为云 APM（APMS）· 面向 kimi-game-rank 的落地方案

---

## 0. 一句话目标

给站点加一套「**真实用户视角**」的质量监测体系：**错误可定位、性能可量化、异常可告警**。
采集用一个**独立的 ES5 脚本**（`assets/js/monitor.js`），确保在**低版本浏览器内核**上也能运行；
数据上报到站点自有后端，在**总管理员控制面板**中集中呈现。

---

## 1. 对标调研：华为云 APM 功能全景

华为云 APM 是「全链路应用性能管理」，涵盖**前端监控 + 应用性能监控**，功能条目如下（据官方产品文档）：

| # | 华为云 APM 功能 | 说明 | 本项目落地策略 |
|---|---|---|---|
| 1 | 应用指标监控 | JVM/GC/服务调用/异常/外部调用/数据库访问/中间件指标 | **裁剪**：无 JVM；改为 PHP 端请求耗时/慢查询/异常指标 |
| 2 | 调用链追踪（Trace） | 还原请求在服务间的完整调用链 | **裁剪**：单体应用，落地为「单请求内阶段耗时」（路由→DB→渲染→响应） |
| 3 | 应用拓扑 | 自动生成服务/中间件/接口依赖拓扑 | **不适用**：单体 + 一个管理员库，无拓扑价值 |
| 4 | URL 跟踪 | 跟踪重要接口与下游调用关系 | **落地（简化）**：重点接口白名单，单独统计成功率/耗时 |
| 5 | 智能告警 | 达阈值触发告警并上报 | **落地**：阈值规则 + 站点内告警记录 |
| 6 | 探针/Agent 管理 | 查看 Agent 状态、启停 | **落地（简化）**：采集开关 + 采集状态 |
| 7 | **前端监控（Web/H5）** | **本次核心** | **重点落地** |
| 8 | 链路追踪 | 分布式调用链 + 日志关联 | 不适用（单体） |
| 9 | App 监控 | Android/iOS/鸿蒙崩溃、ANR、卡顿 | **不适用**：本项目是网页（未来若有 App 端另议） |
| 10 | 系统管理 | 采集中心/数据脱敏/用量统计/访问密钥/通用配置 | **落地**：脱敏策略 + 采集配置 + 用量统计 |

### 1.1 前端监控（Web）功能细目（重点对标）

官方「Web 监控」分 8 大版块，本项目逐一落地：

| 版块 | 官方指标 | 本项目落地 |
|---|---|---|
| **总览** | UV、PV、平均加载时间、JS 错误数/错误率、慢接口占比（>1000ms）、接口成功率 | ✅ 全部 |
| **加载性能** | 首屏时间、白屏时间、可交互时间；特征统计（按页面聚合） | ✅ 全部 |
| **API 请求** | 调用次数、成功率、平均耗时、慢接口占比、TOP 慢接口 | ✅ 全部 |
| **JS 稳定性** | JS 错误数、错误率、错误 TOP、堆栈、影响用户数 | ✅ 全部 |
| **访问分析** | PV/UV、访问量 TOP5 页面 | ✅ 全部 |
| **会话追踪** | 慢请求 / 慢加载 / 慢交互 / 崩溃错误 的会话还原 | ✅（简化：按会话聚合时间线） |
| **自定义上报** | 业务自定义埋点（如登录耗时） | ✅ 提供 `window.__mon.track()` |
| **网络分析** | 按网络类型（2G/3G/4G/WiFi）聚合 | ✅（`navigator.connection`，缺失则跳过） |
| 场景分析 | 自定义场景跟踪 | ✅（自定义上报的聚合视图） |

**官方筛选维度**：站点、运营商、地域、浏览器、操作系统、时间（近20分钟/1h/3h/6h/1天/今天/昨天/7天/30天/自定义）。
**本项目落地维度**：页面、浏览器、操作系统、设备/屏幕、网络、时间；地域/运营商复用已有 IP 归属地。

## 2. 可行性裁剪（明确不做）

- Java 探针 / JVM / GC / 字节码增强 —— 无 JVM。
- 应用拓扑、分布式调用链、SkyWalking/OpenTelemetry —— 单体应用。
- App 端崩溃 / ANR —— 无 App 端。
- 跨账号 / IAM —— 单站单管理员体系。

> 以上不做项在面板中不出现，避免「有入口无数据」。

---

## 3. 指标口径（与官方对齐）

- **PV**：每次页面打开/刷新计 1 次。
- **UV**：同一访客一天内多次访问计 1 次（以本地匿名访客 id 去重）。
- **平均加载时间**：`loadEventEnd - navigationStart` 的均值。
- **首屏时间**：`performance` 取首屏（无标准 API 时用 FP/FCP 或 DOMContentLoaded 近似）。
- **白屏时间**：`domLoading → 首次绘制`。
- **可交互时间**：`DOMContentLoaded`（或 TTI 近似）。
- **JS 错误率** = JS 错误总数 / 页面运行次数。
- **慢接口占比** = 耗时 > 1000ms 的接口数 / 接口总数。
- **接口成功率** = 成功接口数 / 接口总数。
- **Apdex**（应用性能指数）= (满意数 + 容忍数/2) / 总数，阈值默认 T=1.2s。

| page | VARCHAR(191) | 页面路径 |
| ua | VARCHAR(255) | User-Agent（脱敏） |

## 6. 前端 SDK 设计（`assets/js/monitor.js`）

### 6.1 兼容性（硬约束）
- **纯 ES5**：`var` / `function` / 无箭头函数、无 `const/let`、无模板字符串、无 Promise 语法糖（仅检测）。
- **特性探测**：`performance` / `sendBeacon` / `PerformanceObserver` / `fetch` / `navigator.connection` 全部探测后使用，缺失即降级。
- **全包 try/catch**：任何采集异常都不得影响主站；上报失败静默丢弃。
- **不阻塞**：采集回调最轻量；批量上报异步。

### 6.2 采集器
1. **JS 错误**：`window.onerror` + `window.addEventListener('error', …, true)`（含资源错误）。
2. **未处理的 Promise 拒绝**：`unhandledrejection`（有则用）。
3. **资源加载失败**：捕获阶段 `error` 事件，筛 `IMG/SCRIPT/LINK/VIDEO/AUDIO`。
4. **接口监控**：包装 `XMLHttpRequest.prototype.open/send` 与 `window.fetch`，记录 URL/方法/状态/耗时，>1000ms 标记慢。
5. **页面性能**：`performance.timing`（导航时序）+ `PerformanceObserver`（FCP/LCP/CLS，有则用）。
6. **PV/UV**：进入页面记 PV；访客 id 存 `localStorage`（降级 Cookie），跨天生成新 UV。
7. **环境**：UA、浏览器/OS、屏幕、网络、视口、语言、时区。
8. **自定义埋点**：`window.__mon.track(name, value)`。

### 6.3 上报
- 批量队列：满 N 条或每 10s 触发一次 flush。
- 通道：`navigator.sendBeacon`（首选，不阻塞卸载）→ `XMLHttpRequest`（POST）→ 图片打点（GET，极长 query，兜底）。
- 采样率、每会话上报上限、去重（相同 msg+位置 5 秒内合并计数）。
- **卸载前**：`visibilitychange→hidden` / `pagehide` 时补报性能与剩余队列。

### 6.4 脱敏
- 上报前对 `msg/stack/url` 做基础脱敏：邮箱、手机号、长 token/`key=`/`token=`/`sign=` 参数打码。

---

## 7. 后端采集 API（`api/monitor.php`）

- `action=collect`：接收 `{sid, page, events:[…]}` 批量；限速（按 IP+session）；体积上限（如 128KB）；字段白名单；写库。
- `action=toggle` / `action=config`：采集开关、采样率（管理员）。
- 完全 fail-soft：任何异常返回 `{ok:true}` 但不写库，绝不影响前端。
- IP 只存 `sha256(盐+IP)` 指纹。

## 8. 管理面板「网页异常监测」（仅主管理员）

位置：控制面板内，紧随「数据总览 / 趋势统计」之后（管理员专属区块）。

子视图（Tab 切换，自绘，不用原生控件）：
1. **总览**：PV、UV、平均加载、JS 错误数/率、慢接口占比、接口成功率、Apdex；趋势折线；8 类 TOP5。
2. **JS 错误**：错误列表（按 msg+位置分组、次数、影响 UV、最近堆栈）。
3. **接口**：调用次数、成功率、平均耗时、慢接口占比、TOP 慢接口。
4. **加载性能**：平均首屏/白屏/可交互、慢页面 TOP。
5. **资源**：加载失败的资源清单。
6. **分布**：浏览器 / 操作系统 / 设备屏幕 / 网络 / 地域。
7. **告警**：规则列表 + 触发记录（可确认）。
8. **设置**：采集开关、采样率、脱敏开关、数据保留天数。

---

## 9. 告警

- 规则：错误率 > 阈值、慢接口占比 > 阈值、单错误 5 分钟突增 N 次、接口成功率 < 阈值。
- 触发写入 `web_alerts`，面板顶部红色提醒；可选在站内公告/管理员通知中提示。
- 阈值可在「设置」内调整，存 `settings`。

## 10. 兼容性与性能预算

| 项 | 目标 |
|---|---|
| 浏览器 | ES5 可运行（IE9+ 级内核、老 Android WebView、UC/QQ 内核均可） |
| SDK 体积 | ≤ 8KB（未压缩） |
| 运行时开销 | 单事件 < 1ms；上报异步、不影响 FCP |
| 存储增长 | 明细表按保留天数清理（默认 7 天，cron 顺手） |
| 网络 | 批量上报 + sendBeacon；失败不重试轰炸 |

## 12. 验收标准

1. 老内核浏览器打开站点，`monitor.js` 不报错、页面功能不受影响。
2. 人为制造 JS 错误 / 接口 500 / 慢接口 / 图片 404，面板对应视图能出现记录。
3. PV/UV 与站点实际访问一致（去重正确）。
4. 上报失败（断网）时前端无感、主站无影响。
5. 上报数据中不含明文 IP、邮箱、手机号、token。
