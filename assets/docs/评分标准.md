# 评分标准 — Kimi游戏榜

> 站内「评分标准」正式文案 · 算法全公开版
> 本页公布本站的**全部评分算法**：所有公式、权重与阈值均来自运行中的配置，可对照复核。

## 评分总览

本站对每件收录作品做**层级化六维评分**。六维归为**三支柱**，单维满分 **200**，总分满分 **1200**。

| 支柱 | 维度 | 满分 | 衡量什么 |
|:---:|---|:---:|---|
| **作品质量** | 可玩性 | 200 | 可运行性、交互密度、说明完整度 |
| | 创意 | 200 | 标题独特性、表达多样性、形式创新 |
| | 深度 | 200 | 文本规模、结构、代码深度、讨论深度 |
| **作者投入** | 体量 | 200 | 文件体量、代码规模、文本投入 |
| | 用心 | 200 | 由投入推导的用心：交代是否清楚、是否交付成品 |
| **社区认可** | 口碑 | 200 | 社区互动量（点赞 / 评论 / 收藏） |

总分由三支柱**加权几何**聚合——**任一支柱弱，都会乘性压制总分**（短板效应）；而不是各维相加各自为政。

> 全部评分由系统按下列公开算法**自动计算**；**站长也可能根据作品实际情况对个别作品的评分做人工修正**，修正记录在作品页可见。本站**不接受任何形式的调分申请**。

## 一、记号与基础函数

| 记号 | 含义 |
|:---:|---|
| L / C / F | 点赞数 / 评论数 / 收藏数 |
| T / X / B | 标题 / 作者配文（简介） / 正文 |
| H | 作品文件（HTML + 其引用的脚本；无则记空） |
| bytes / lines / funcs | H 的字节数 / 行数 / 函数出现次数 |
| age | 作品上架至今小时数 |

```
clamp01(x)   = 把 x 限制到 [0, 1]
lns(x, n)    = ln(1+x) / ln(1+n)          ← 边际递减
bell(x, a, b) = x 落在 [a, b] 取 1，越界按 decay=10 线性衰减到 0
```

> 作品中的**媒体数量（图片 / 音频 / 视频）不参与任何维度计分**，仅在作品页展示。

## 二、各维公式（6 × 200 分）

**① 可玩性**
```
e1 可运行 = 有作品文件或可分享产物 → 1
e2 交互   = min(1, 交互标签数 ÷ 12)      （button/input/select/textarea/canvas/svg）
e3 说明   = 命中词表 {操作,点击,选择,输入,按键,拖动,关卡,难度,模式} 的比例
可玩性 = 200 × clamp01(0.40×e1 + 0.40×e2 + 0.20×e3) × (可运行 ? 1 : 0.8)
```

**② 创意**
```
s1 标题独特性 = 1 − 与库内最相似作品标题的 2-gram 相似度（最多比对 300 件；空库记 1）
s2 标题长度   = bell(len(T), 4, 20)
s3 表达多样性 = 文本去重词数 ÷ 总词数
s4 形式创新   = min(1, (0.15×有产物 + 0.10×有作品文件) ÷ 0.25)
创意 = 200 × clamp01(0.20×s1 + 0.10×s2 + 0.40×s3 + 0.30×s4)
```

**③ 深度**
```
d1 文本 = min(1, len(X+B) ÷ 1200)
d2 结构 = min(1, (段落 + 列表标记) ÷ 8)
d3 代码 = max( min(1, lines ÷ 800), min(1, funcs ÷ 60) )
d4 讨论 = clamp01( lns(C, 30) )
深度 = 200 × clamp01(0.30×d1 + 0.20×d2 + 0.30×d3 + 0.20×d4)
```

**④ 体量（成本）**
```
c1 文件 = min(1, bytes ÷ 300KB)
c2 代码 = min(1, lines ÷ 1200)
c3 文本 = min(1, len(X+B) ÷ 3000)
体量 = 200 × clamp01( (0.44×c1 + 0.31×c2 + 0.25×c3) ÷ 权重和 )
（无作品文件时剔除 c1、c2，只按文本量计）
```

**⑤ 用心（依据投入推导）**
```
基线     = 体量维得分 ÷ 200
a1 交代 = 作者配文 / 正文的用心程度（0–1；先由模型判定，不可用则按配文长度分级）
a2 交付 = 有作品文件或可分享产物 → 1；否则 0
用心 = 200 × clamp01(0.35×基线 + 0.45×a1 + 0.20×a2)
```
> 没有作者行为数据时「态度」无法独立测量，而「体量」本身就是投入的客观度量。以它为基线，再用「交代是否清楚」「是否交付成品」区分用心程度。

**⑥ 口碑（贝叶斯收缩）**
```
s_raw = 0.45×lns(L,100) + 0.35×lns(C,50) + 0.20×lns(F,30)
n     = L + C + F
s     = (25×s_prior + n×s_raw) ÷ (25 + n)      ← s_prior 为全站口碑均值
口碑  = 200 × s × (上架 24 小时内加成 ≤ 20%)
```
> **贝叶斯收缩**：互动样本少时，口碑向全站均值靠拢，杜绝「1 个赞封神」；互动越多越接近真实水平。

## 三、层级权重（AHP × CRITIC）

**① 主观权重（AHP，Saaty 1980）** —— 由权威的两两比较判断矩阵导出：

```
支柱判断矩阵 A：
       质量   投入   认可
质量    1      2      3
投入   1/2     1      2
认可   1/3    1/2     1
→ 支柱权重 [0.5396, 0.2970, 0.1634]；λmax≈3.009，CR=0.008 < 0.1（通过一致性检验）

支柱内（作品质量）：可玩性 / 创意 / 深度 = 0.45 / 0.25 / 0.30
支柱内（作者投入）：体量 / 用心       = 0.55 / 0.45
```

**② 客观权重（CRITIC）** —— 由**全站语料**计算，衡量指标的**对比强度**与**冲突性**：
```
对归一化后的六维矩阵：C_j = σ_j × Σ_k (1 − r_jk)
（σ_j 为第 j 维标准差；r_jk 为 j、k 两维的相关系数）
客观权重 w_obj ∝ C_j
```
> 一个维度若与其它维度**高度相关**（信息重叠），其权重会被调低；反之信息独立的维度权重更高——这就是各维度之间「关联」的数学化。

**③ 组合权重**
```
w = 0.5 × w_AHP + 0.5 × w_CRITIC
```
（语料样本不足时自动退回纯 AHP 权重。）

## 四、汇总与评级

**支柱归一值**：各支柱内维度按其组合权重加权平均后除以 200，得 [0,1]。
**总分（加权几何）**：
```
P' = 0.10 + 0.90 × P                         （下限，避免某支柱归零）
总分 = 1200 × Π ( P'^α )                       （α 为支柱权重）
```

**评级**：按**累计名次百分比**定级——并列同分算同一档，**每档不超过配额**（SSS 前 2%、SS 前 10%、S 前 25%、A 前 50%、B 前 75%、其余 C）。让评级随生态水位浮动，而不是被固定分数线拉开差距。

| 评级 | 分位 |
|:---:|:---:|
| ✨ SSS | 前 2% |
| SS | 前 10% |
| S | 前 25% |
| A | 前 50% |
| B | 前 75% |
| C | 其余 |

> 语料不足时退回一组固定分数线（如 1000 / 870 / 780 / 660 / 540）。

## 五、信号缺失与异常

1. **信号缺失**：某信号无法取得时，**剔除该信号并把其余权重等比重归一化**，不按 0 计分——资料少不吃亏。
2. **异常值**：互动数据短期陡增会被标记复核；确认异常可清除相关数据并重算。
3. **冷启动**：全站语料不足时，客观权重与分位评级自动退回主观权重与固定分数线，不影响计分。

## 六、数据来源与更新时机

| 项 | 说明 |
|---|---|
| 数据来源 | 作品在 [Kimi 社区](https://www.kimi.com)的**公开信息**：标题、配文、正文、点赞 / 评论 / 收藏数、作品文件及其引用的脚本 |
| 首次计算 | 作品**被收录时**计算六维并写入 |
| 后续计算 | 每次**同步到新数据**时重算（是否覆盖旧分见「评分方式」开关） |
| 更新节奏 | 由管理员配置的同步节奏决定 |
| 客观权重 / 评级 | 每天依据全站语料刷新一次 |

## 七、逐维「计什么 / 不计什么」

| 支柱 | 维度 | 计入（可量化） | **不计入**（主观） |
|:---:|:---:|---|---|
| 质量 | 可玩性 | 可运行性、交互标签、说明词 | 「好不好玩」 |
| 质量 | 创意 | 标题独特性与长度、表达多样性、形式创新 | 「有没有创意」 |
| 质量 | 深度 | 文本、结构、代码行数与函数数、讨论 | 「深不深」 |
| 投入 | 体量 | 文件体量、代码规模、文本 | 无法量化的努力 |
| 投入 | 用心 | 由投入推导 + 配文用心 + 成品交付 | 「态度好不好」 |
| 认可 | 口碑 | 点赞、评论、收藏（贝叶斯校正） | 浏览量、站外热度 |

**关键说明**：本站**不对主观的创意、美感、有趣程度做任何人工判断**，六维全部建立在**可量化、可复核**的信号之上——这是本榜"算法全公开"的前提。

## 八、自查：如何提升分数

| 你希望提升 | 可以做什么 |
|---|---|
| 可玩性 | 确保作品**可运行**；加入按钮 / 画布等交互；写清操作说明 |
| 创意 | 起一个不重复的标题；把配文写充实、用词多样；提供可分享产物 |
| 深度 | 正文写清玩法与设计；善用分段与列表；代码按功能拆分函数 |
| 体量 | 无法"优化"——客观投入，鼓励认真做而非凑数 |
| 用心 | 把作品做完整、投入更多；在配文里交代清楚玩法与更新 |
| 口碑 | 让作品被更多人**点赞、评论、收藏**；首日曝光加成有窗口期 |
